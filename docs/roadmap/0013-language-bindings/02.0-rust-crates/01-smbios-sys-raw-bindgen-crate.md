# 01 - `smbios-sys` raw bindgen crate

**Parent story:** [README.md](README.md)
**Status:** ⬜ Not started
**Depends on:** Story 01.0 (acquisition strategy, sync check)

## Objective

Produce a `-sys` crate that locates/builds `smbios_c` per Story 01.0
Task 01's decision, runs `bindgen` against
`smbios_c/include/smbios/smbios.h` at build time (or ships a
pre-generated, checked-in binding file regenerated by a documented
script - decide and record which, per Constraints), and exposes exactly
the 13 raw `unsafe extern "C"` functions and the opaque handle/enum
types `bindgen` produces - nothing hand-added.

## Files

- **Create** `bindings/rust/smbios-sys/Cargo.toml`: `links =
  "smbios_c"`, a `build-dependencies` entry on `bindgen` (and `pkg-config`
  or an equivalent locator crate, per Story 01.0 Task 01's chosen
  mechanism).
- **Create** `bindings/rust/smbios-sys/build.rs`: locates `smbios_c`
  (Story 01.0 Task 01's chosen default + override), emits the correct
  `cargo:rustc-link-lib=smbios_c` / `cargo:rustc-link-search=...`
  directives, and invokes `bindgen::Builder` against
  `smbios_c/include/smbios/smbios.h`.
- **Create** `bindings/rust/smbios-sys/src/lib.rs`: `#![no_std]`-compatible
  if feasible (no allocation needed for raw FFI declarations themselves),
  re-exporting `bindgen`'s generated bindings; a module-level doc comment
  stating this crate is raw/`unsafe` only and pointing to the `smbios`
  wrapper crate (Story 02.0 Task 02) for safe use.

## Constraints

- Decide and record (in `bindings/rust/smbios-sys/README.md` or
  `docs/dev/language-bindings.md`): generate bindings at **build time**
  via `bindgen` in `build.rs` (requires `libclang` on every build
  machine, including every `cargo add` consumer's own machine - a real
  adoption cost) versus **check in** a `bindgen`-generated file,
  regenerated by a maintainer-only script when `smbios.h` changes (lower
  consumer-side cost, risk of drift between the checked-in file and a
  newer `smbios.h` if the regeneration step is forgotten - mitigated by
  Story 01.0 Task 02's sync check running regardless of which option
  wins).
- `smbios-sys` crate version itself does not need to track `smbios_c`'s
  `SMBIOS_C_VERSION` (currently `1.0.0`) number-for-number, but its own
  `README`/`Cargo.toml` `description` must state which `smbios_c`
  version range it was generated against and tested with (plan.md's Key
  constraints, "independently-versioned").
- No `unsafe` abstraction beyond what a direct FFI declaration requires
  - no `Drop`, no `Result`, no hidden allocation. That is Task 02's job.

## Tests

- A `build.rs` smoke test (run as part of `cargo test` or a dedicated
  CI step): the crate builds successfully against a real, locally built
  `smbios_c` (per Story 01.0's acquisition path), and the generated
  bindings' symbol names match Story 01.0 Task 02's sync check with zero
  diff.
- A minimal `#[test]` calling `smbios_open`/`smbios_close` directly
  through raw `unsafe` FFI, confirming the raw symbols link and execute
  without crashing - not asserting on parsed SMBIOS content (that is
  Story 04.0's job).
